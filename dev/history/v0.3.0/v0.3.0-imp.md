# OfficeAssist v0.3.0 CSV・TSV取り込み設計案

作成日: 2026-11-06。状態: 設計案、製品コード未変更。版番号は仮置き。[要求の正本](v0.3.0-req.md)のR01～R07を対象とする。以下の既定値・例外処理・追加機能は、指定済みの要望を成立させるための提案であり、実装済み・承認済みではない。

## 1. 現行実装から分かった課題

調査基点はOfficeAssistの`c1c73ef`。公開v0.2.1の製品コードは`489101f`と同じで、その後の変更は公開結果の文書のみ。

| 現行の構成 | 今回必要な変更 |
| --- | --- |
| `TabularFiles.Read`が全バイト・全行をメモリーへ展開する。最大50ファイル、1ファイル20MiB、合計64MiB、合計20万セル。 | プレビューの非表示だけでは読み込み負荷は減らない。受信、解析、行加工、プレビュー、書込みを分離する。 |
| `ExcelDropService.QueueInsert`がOLEのDrop応答前にCSV・TSVをすべて解析する。 | 応答前には入力の保持と最小限の検査まで行い、全解析は応答後に実行する。 |
| `TabularImportSelection`が元ファイルの列番号に設定を保持する。 | 加工後・結合後の列定義に設定を対応させる。 |
| `TabularImportForm`は仮想グリッドだが、背後の`string[][]`には全データがある。 | ディスクに保持したデータから必要なページだけを取得する。 |
| `ExcelTabularInserter`はドロップ元ウィンドウの現在選択へ依存する。新規ブック・シートでは1ファイル1シート。 | 明示したブック・シート・アドレスで配置を解決し、結合時には出力を1表として扱う。 |
| 複数段階で`ExcelValues`の全配列を作り直す。 | 全件検証済みの計画を共有し、書込み時にチャンク単位で値を生成する。 |
| 画像とCSVの表示にCOMの`Address`既定値を使う箇所がある。 | 表示用アドレスを共通化し、内部の範囲識別・式と分離する。 |

既存仕様を上書きする説明を`docs/guide.md`へ先に載せず、実装が確定するまで本書で管理する。

## 2. 画面の構成

```text
展開先 [指定セル ▼]  ブック [売上.xlsx ▼]  シート [集計 ▼]  セル [B3       ]
先頭から除外 [0] 行  末尾から除外 [0] 行  [ ] 空欄行を除外
[ ] すべてのファイルを結合  [✓] 先頭行を見出しとして扱う  結合基準 [列順 ▼]
プレビュー [各ファイル先頭10行 ▼]                       [ファイル順序…]
ファイル名を選択 [01.csv ▼]  [ ] すべてのファイルに適用
┌──────────┬──────────┬──────────┐
│ 列名・形式・小数桁 │ 列名・形式・小数桁 │ 列名・形式・小数桁 │ ← 横方向の列設定
├──────────┼──────────┼──────────┤
│ 実データ          │ 実データ          │ 実データ          │
│                  │                  │                  │ ← 加工後プレビュー
└──────────┴──────────┴──────────┘
進捗・対象件数・出力範囲                            [取り込む] [キャンセル]
```

「ファイル順序…」と進捗表示は追加推奨。製品画面に副題・操作説明のキャプションは置かない。補足はツールチップ、問題は該当入力のエラー表示と前面ダイアログで伝える。画面は最大化可能とし、狭い幅では入力行を折り返す。横並び列設定とデータの横スクロールは同期する。プレビューOFFでも列設定は表示し、列設定側だけで横へ移動できる。

### 2.1 入力の有効条件と既定値案

| 項目 | 既定値案 | 条件・動作 |
| --- | --- | --- |
| 展開先 | 指定セル | 新しいブック／新しいシート／指定セル。 |
| ブック・シート・セル | ドロップ元の選択を取得 | 指定セルでは変更可能。ブック変更時はシート一覧を更新し、無効な旧シート指定を残さない。 |
| 先頭・末尾から除外 | 各0行 | 全ファイルへ同じ数を適用。0以上の整数。 |
| 空欄行を除外 | OFF | 元データ保持を優先。ONで各ファイルの空欄行を除く。 |
| すべてのファイルを結合 | OFF | 既存のファイル別展開を初期状態として維持。 |
| 先頭行を見出しとして扱う | 加工後データから推定 | 現行の自動推定を維持し、ユーザー変更を優先。ファイル途中の繰り返し見出しは自動削除しない。 |
| 結合基準 | 列順 | 結合ONかつ見出しONのときだけ表示。その他は列位置で対応させる。 |
| プレビュー | 各ファイル先頭10行 | 表示量だけを変更し、出力するデータの件数を減らさない。 |
| すべてのファイルに適用 | OFF | 結合OFF時の列形式・小数桁だけに作用する。行除外は常に全ファイル共通。結合ON時は非表示。 |

結合ONでは「ファイル名を選択」のラベルとコンボを取り除き、結合後の1表を表示する。ファイル順の編集は別ボタンとし、プレビュー対象ファイルを選ぶ機能を残さない。

### 2.2 指定セルとExcel接続

- ブックはドロップ先と同じExcelインスタンスで開いているものから選ぶ。別Excelプロセスのブック選択は追加候補とし、最初の対象に含めない。
- ブック・シートは選択式コンボ、セルは編集可能テキストとする。ブックの表示は名前、同名識別はフルパスまたは未保存ブックのセッションIDをツールチップに使う。名前だけで接続し直さない。
- アドレスはA1形式。`$B$3`を貼り付けても受理し、確定時に`B3`へ正規化する。数式、外部ブック参照、3D参照、行全体・列全体、名前定義は受け付けない。シートは別フィールドで指定する。
- 初期値はドロップ時の`RangeSelection`。複数選択も保持し、`B3:D7,F3:H7`のように表示する。アドレス入力の区切りはカンマに統一する。
- 範囲を指定した場合、各範囲の左上を開始セルとする。範囲の高さ・幅に収まるような縮小・切り捨てはしない。実際の出力先範囲を事前計算して表示する。
- 結合OFF時は既存どおり各選択範囲へ順次配置し、範囲不足なら最後の出力の下へ1行空ける。結合ONでは単一の連続範囲を要求する。初期選択が複数範囲なら、勝手に先頭だけを採用せずアドレスの修正を求める。
- 「新しいシート」ではブックだけ変更可能。シートとセルは作成予定値・A1を表示して編集不可。「新しいブック」ではブック・シートは作成予定値、セルはA1として編集不可。作成するシート名は既存の重複回避を維持する。
- ダイアログを開いてからアクティブセルが変わっても、ユーザーが明示した指定先は追従させない。実行直前に同じブック・シートが存在し書込可能か再検査する。

### 2.3 セルアドレスの表示

共通の表示処理で`Range.Address(RowAbsolute: false, ColumnAbsolute: false, ReferenceStyle: xlA1)`相当を使う。画像の設定ツールチップ・成功メッセージ、CSVの衝突警告・出力先、状態表示も対象とする。例: `売上.xlsx / 集計 / B3:F20`。

メッセージ全体へ`Replace("$", "")`を行わない。`売上$確定.xlsx`というファイル名、シート名、元データの通貨記号、IMAGE式やExcelの絶対参照を壊さない。内部識別用アドレスは表示と分け、範囲の同一性判定や既存の式は変更しない。[Range.Address公式仕様](https://learn.microsoft.com/en-us/office/vba/api/excel.range.address)に基づく。

## 3. 行の加工

### 3.1 処理順序案

1. CSV・TSVを引用符対応で解析し、論理レコードを得る。
2. 各ファイルから先頭Nレコードと末尾Mレコードを除外する。
3. ONなら、残ったレコードの空欄行を除外する。
4. 見出しONなら、残った最初の1レコードをそのファイルの見出しとして分離する。
5. 列の対応を解決し、データをファイル順で連結する。
6. 結合ONでは左端へファイル名列を追加する。
7. 列形式を推定・手動指定し、全データを検証して書き込む。

引用符内の改行は同一レコードであり、行数を増やさない。先頭・末尾の除外数には見出しも含まれる。見出しONでも、除外前の1行目を特別扱いしない。例: 説明2行、見出し1行、データ100行、集計1行なら「先頭2・末尾1・見出しON」でデータ100行になる。

末尾除外はファイルごとに適用し、結合後の全体末尾だけを削らない。先頭・末尾の除外は空欄除外より先なので、N・Mには空欄レコードも数える。CSVの通常の最終改行は追加の空レコードに数えない。行加工でデータ値の空白・改行そのものを変更しない。

### 3.2 空欄・空ファイル・境界

- 空欄行は「すべての項目が空文字」の論理レコードとする。`,,`や`"",""`も空欄。空白・全角空白だけの文字列は値として保持する。空白だけも削除する設定は追加候補。
- `N + M >= 元レコード数`ではデータ0行となり、そのファイルをスキップする。見出しだけ残ったファイルは列定義に参加するが、データ行を作らない。
- スキップされたファイルと理由・除外件数を結果に残す。全ファイルでデータ0行なら書込みせず、設定画面を維持して修正を求める。
- 除外対象にもCSV構文の検証は行う。引用符が閉じないなど、レコード境界自体が不明なファイルを「末尾除外」で黙って通さない。
- 元ファイルID・論理レコード番号・物理行番号範囲を保持し、加工後の変換エラーから原位置へ戻れるようにする。

## 4. ファイル結合

### 4.1 出力と順番

結合ONは1つの出力表。新しいブックなら1ブック1シート、新しいシートなら指定ブックへ1シート、指定セルならその開始位置へ1表を書き込む。ファイル間の空行は入れない。ファイル内の順序は変更しない。見出しONでは出力見出しは1回だけ、OFFではデータの前に見出しレコードを新設しない。

左端は常にファイル名の文字列列。値は拡張子付きベース名とし、フルパスは出力しない。見出しONでは`ファイル名`という出力見出しを使う。入力見出しと衝突する場合は`ファイル名（元ファイル）`、さらに重複すれば連番を付ける。生成列は文字列（書式設定）固定とする。同じベース名の別フォルダのファイルは取り込めるが、識別が曖昧なことを事前通知する。

結合順は受信したファイル配列の順とし、Explorerの見た目の並びと一致すると保証しない。順序の確認・上下移動・名前順への変更を行う「ファイル順序…」を今回の追加推奨とする。同じファイルを重複指定した場合も黙って除外せず、取り込み前に確認できるようにする。

### 4.2 列の対応

| 条件 | 推奨する対応 |
| --- | --- |
| 見出しOFF | 列位置で結合。出力幅は全ファイルの最大列数、不足分は空セル。UIは列1・列2…と表示。 |
| 見出しON・列順 | 列位置で結合。既存位置の出力見出しは最初のファイルの値。後続だけにある位置は、その位置を初めて持つファイルの見出しを採用。列数差・同じ位置での見出し差を警告する。 |
| 見出しON・列名 | 見出し名で照合。最初のファイルの列順を基本に、後続で初めて出現した列を右へ追加する（全列の和集合）。そのファイルにない列は空セル。 |

列名の照合キーはBOM除去後・前後空白を除いた文字列とし、大文字小文字・全角半角は区別する。出力見出しは最初に採用した表記を保持する。照合のためにデータ値をtrimしない。

列名方式では同一ファイル内の空の見出し・照合キーの重複はエラー。後勝ち上書きや勝手な連番対応はせず、列順へ変更するか入力修正を求める。見出しより長いデータ行も列名が確定できないためエラー。短い行は不足分を空セルとする。列順方式では空の見出しを`列N`で補い、重複見出しを持つ別列も列位置で保持する。

具体例（結合基準「列名」）:

```text
01.csv: 氏名,金額       → 山田,100
02.csv: 金額,氏名,備考  → 200,佐藤,追加

ファイル名 | 氏名 | 金額 | 備考
01.csv     | 山田 | 100  |
02.csv     | 佐藤 | 200  | 追加
```

同じ入力を列順で結合すると`02.csv`の200は1列目、佐藤は2列目に入る。意図しない位置対応を防ぐため、見出しの相違は実行前に表示する。

### 4.3 列設定の保持

結合ONでは結合後の列ごとに1つの形式と小数桁を持つ。型推定は全入力から対応する値を集めて行い、ファイル単位の型を後から強制的に一致させない。数値と非数値の混在は文字列（書式設定）へ寄せ、手動指定を優先する。

設定は列順なら出力列番号、列名なら正規化キーに対応させる。設定変更で出力列の意味が変わったときに別列へ誤転用しない。結合OFFのファイル別手動設定を別に保持し、ON→OFFで戻せるようにする。初めてONへ切り替えるときは結合後に再推定する。戻すまでの設定はセッション内に保持し、保存機能の採用とは分ける。

## 5. プレビューと大容量対応

### 5.1 表示モード

| モード | 表示するデータ | 実行への影響 |
| --- | --- | --- |
| しない | データ行を作らず、列設定と件数・進捗だけを表示。 | 全件の解析・変換・衝突検査は省略しない。 |
| 各ファイル先頭10行 | 行除外・見出し除去後のデータを各ファイル最大10行。結合ONでは同じ列対応・ファイル名列で連結表示。 | 11行目以降も出力する。全体の先頭10行だけにしない。 |
| すべて | 加工後の出力表全体を仮想グリッドで参照可能にする。 | 全行を画面部品やメモリー配列へ一括生成しない。 |

10行モードでは見出しを10行へ含めない。結合ONのサンプル間に省略された行があっても、架空の「…」データ行を挿入しない。実出力行番号と元行番号を行見出し・ツールチップに使い、省略件数を状態表示へ出す。プレビューは加工後の生データを示し、列形式によるExcel表示の丸めとは区別する。

### 5.2 受信・解析・保持

1. OLEのDrop内では対応拡張子・件数・サイズ・読取可否を確認し、全入力の読取ハンドルを確保する。送信元が消したり書き換えたりできない共有モードを選び、元ファイルへのMoveは実行しない。保持できなければCopy成功を返さない。
2. OLEへ応答した後、設定画面を前面表示する。保持したストリームから専用の一時領域へ非同期でコピーし、チェックサムを確定する。ハンドル共有を制限できない環境では保持方法を実証できるまで受信を拒否し、短命ファイルを見失う構成にしない。
3. 解析ワーカーはExcel COMに触れず、ストリームを論理レコードへ解析する。メモリー全体へバイト列・文字列・行配列を重複確保しない。UTF-8/UTF-16 BOMと現行のUTF-8→CP932判定を維持し、再読込が必要なら保持済みコピーから行う。
4. 解析結果は長さ付きのレコード、元行情報、疎な行位置索引としてローカルの専用一時領域に保存する。末尾M行除外は件数確定後の論理スライスとし、M件をメモリーに保持しない。
5. プレビューはページ単位の有界キャッシュを使う。UIのセル取得イベント内で大きな同期I/Oをしない。読み込み中のページは非同期取得後に再描画する。
6. 設定を変えたら世代番号を更新し、旧世代の解析・推定・プレビューをキャンセルする。行除外・列対応の変更は保持したレコードから再構築し、入力ファイルを読み直さない。
7. 一時領域は利用者ごとのローカル領域に作り、所有者のアクセス権を維持する。入力コピー・レコード保持・索引・復元用退避の使用量を合計管理し、容量不足時は書込み前に停止する。完了・キャンセルで自分の一時領域だけを削除する。異常終了後の残留は次回起動時に所有情報と非稼働を確認して整理する。元データを通常ログ・公開リポジトリへ書かない。

解析エラーはCopy応答後に発生し得るが、独自取り込みとしてエラーを前面表示し、Excel標準オープンへ戻さない。ドロップを受理しなかった場合のExcel側の挙動と、受理後の解析エラーを別々に検証する。

### 5.3 上限と応答性の方針

Excelの行列数と1セル文字数の上限は超えられない。最大1,048,576行、16,384列、1セル32,767文字を前提に、実際の対象シートのRows/Columnsを取得して判定する。結合時は追加するファイル名列と見出し1行も数え、開始セルのオフセットを含める。数値の有効桁数15桁も文字列推定の根拠として維持する。[Excel公式仕様](https://support.microsoft.com/en-us/excel/excel-specifications-and-limits)に基づく。

現行の20MiB/64MiB/20万セルの制限を無条件に外さない。設計上は固定メモリーに依存しない構成へ変えたうえで、暫定目標を「1ファイル128MiB・合計512MiB・合計200万出力セル・50ファイル」とする。結合時の空セル補完とファイル名列もセル数へ含める。これは性能検証前の提案であり、製品の対応保証値ではない。まず現行上限で正しさを確認し、その後に多行・多列・長文・低メモリー・キャンセル試験を行って採用値を決める。

提案する計測目標は、保持可能なローカルファイルで全解析の終了を待たず画面を出すこと、解析中もUI入力を受け付けること、ワーカーのキャンセルを1秒程度の間隔で確認すること。ExcelのCOM呼び出し中のキャンセル完了時間は保証せず、呼び出し終了後のチャンク境界で受け付ける。入力件数、処理時間、最大メモリー、一時容量を合成データで計測する。

## 6. Excelへの書込みと失敗時の扱い

- 指定ブック・シート・範囲を明示的に解決する。COMは所有するSTAスレッドからだけ呼び、解析ワーカーへCOMオブジェクトを渡さない。
- 行加工・列対応・全件型検証・出力件数を先に確定する。プレビュー10行だけの型推定結果で、11行目以降の不正値を黙って変換しない。全件推定中は状態を表示し、列形式の手動指定は保持する。
- 全出力範囲について、既存の値・数式・結合・保護・読取専用・シート端・範囲間重複を、最初の書込み前に検査する。加えて配列数式・スピル範囲、Excelテーブル・ピボットの占有領域も拒否する設計を推奨する。上書き機能は今回追加しない。
- 書式を適用する「列」は出力表の該当列の範囲であり、ワークシート全列ではない。表の外の書式を変更しない。
- 2万～5万セル程度を初期目安とするチャンク単位で`Value2`へ書き込む。実測で調整し、巨大な`object[,]`を全表分作らない。文字列の書式設定を値代入より先に適用し、数式風文字列の非実行を維持する。
- Excelイベント・計算・画面更新等を変更する場合は元の状態を保存し、終了経路すべてで元に戻す。Excelのウィンドウロックは既存の入れ子管理を維持し、変更先ブックの全対象ウィンドウも同じロックの寿命に含める。
- 解析・検証・書込み中の進捗とキャンセルを追加する。書込み中のキャンセルは新しいチャンクを停止し、既に書いたセルと変更した書式を戻す。新規作成したシート・ブックは今回分だけ破棄する。
- 混在書式の退避は一括取得可能な塊に分け、必要なら一時領域へ退避する。セルごとのCOM往復と無制限のメモリー保持は避ける。従来と同じく完全なトランザクションは保証できず、Excel切断などで復元不能なら残ったブック・範囲を明示する。
- エラーでは設定画面を閉じず、Excelのロックを維持して前面に出す。対象ブック変更・アドレス修正・型変更で再試行できるようにする。対象外のExcelプロセスをロックしたり終了したりしない。
- 複数範囲の使用後の選択移動は出力先のシートに対して行う。元のドロップ先と指定先が異なる場合は元シートの選択を消費しない。完了時に指定先を表示する方針とする。

## 8. CLI設計案

既存の`--import-table --new-book --header --types --decimals --save-as --report`を維持する。今回のオプションは同じ変換処理に渡す。下記は未実装の設計用構文。

```powershell
OfficeAssist.exe --import-table --new-book --header yes --merge --merge-by name `
  --skip-first 2 --skip-last 1 --drop-empty-rows --preview none `
  --save-as C:\work\結合結果.xlsx --report C:\work\結果.json `
  -- C:\work\01.csv C:\work\02.tsv
```

`--merge-by`は`order|name`、`--preview`は`none|first10|all`。CLIが非表示で動く場合はプレビューを構築せず、変換結果と件数がGUIと一致することを検証する。`--merge-by name`と見出しOFFの組合せはエラー。既存`--types`と`--decimals`は結合ONなら生成するファイル名列を除く出力データ列へ適用し、生成列は文字列固定とする。結合OFFでは既存の全ファイル同列数という制限を維持する。

指定セル・新しいシートのCLIは、実行中Excelの一覧を取得する`--list-excel-targets`と、その結果のインスタンスID・ブックIDを使う`--excel-instance`、`--book-id`、`--sheet`、`--cell`を追加する案とする。あいまいなActiveWorkbook接続はしない。同じ表示名が複数ある場合は自動選択せずエラー。安全なCLI検証は専用Excelインスタンス・合成データで行い、利用者の開いたブックへ試験入力しない。

レポートは既定で件数・列設定・除外数・範囲・エラー位置などのメタデータだけとし、現行の値サンプルを残す用途には明示的な`--report-values`を設ける案。設定ファイルによる再実行は追加候補。CLIは既存どおり保存先を黙って上書きしない。
